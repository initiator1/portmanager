Small tool. Local control.

Put localhost
in order.

Install the CLI, create a registry in your workspace, and claim a port for an existing project.

Requires Python 3.11+ and uv. No account or hosted service is needed for the CLI.

Read the full setup guide

Install Portmanager

uv tool install 'git+https://github.com/initiator1/portmanager.git'

Initialize and claim

cd /path/to/your/workspace
portmanager init
portmanager claim ./studio web --kind web
portmanager doctor ./studio

Replace the workspace path and ./studio with your existing project.

Connect the port to your dev command

For a Vite project, use the generated value in your package.json script: 

"dev": "vite --host 127.0.0.1 --port $PM_PORT_WEB"

Then start the project with its settings loaded:

portmanager run ./studio -- npm run dev

This shell example is for macOS and Linux. Portmanager checks supported source declarations; it does not rewrite your app.

A few useful details.

What happens to ports I already use?

Scan first, then preview adoption with portmanager adopt ./studio --dry-run. Adoption registers supported existing bindings. It does not move them or edit your source.

Does it work with coding agents?

Yes. Optional guardrails add managed instruction blocks for supported agent surfaces. Preview changes with portmanager guardrails install --dry-run before installing them.

Can it prevent every port conflict?

It avoids duplicate registry assignments and skips unavailable ports when you claim them. Another process can still take a port later. Validation reports conflicts it can identify. This is early-stage software.

Where does my data go?

The CLI stores registry and generated settings on your machine. These files can contain private project paths; keep them out of public repositories. This landing page adds no analytics or tracking scripts. GitHub's privacy policy applies to hosting.
